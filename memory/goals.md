> **BOOTSTRAP — fill this out when you want the weekly Goal Loop.** <!-- goal-loop:template -->
> While this block is here, the weekly planner skips this file entirely: no goal
> section, no research, no rewrite. Replace the placeholders below with your own
> goals (or run `/goal-review`), then **delete this whole block** to switch the loop on.
> Format and behaviour: `docs/goal-loop.md`.
>
> Each goal is a `## G<number> — Title` heading followed by `- key: value` lines:
>
>     ## G1 — <a short goal title>
>     - outcome: <what is true when this goal is done>
>     - success_signal: <how you would see it moving, in one line>
>     - status: on-track            (or: stalled / blocked / done / paused)
>     - last_moved: <YYYY-MM-DD>    (the last date it really moved)
>     - next_step: <the ONE next concrete action>
>     - repos: ["<folder-name-of-a-sibling-checkout>"]
>     - research_notes:
>     - open_questions: []
>
> - Put `research` in a goal's `next_step` and the loop runs one gated web-research
>   fetch for it (at most two goals a week). A question that reads like a publish,
>   sign-up or payment step is parked for your approval instead of run.
> - `repos` lists checkouts next to this one (or absolute paths); their commits in
>   the last 7 days count as movement.
> - `status: paused ...` keeps a goal on file without weekly questions about it.
> - Anything you write under a goal besides these keys is kept verbatim.
